## 三、核心数据流

```
启动时（一次性）：
  data/*.txt, data/*.md
    → loader.load_documents()          → list[Document]
    → sync_index() 增量同步            → list[Chunk]
    → embedder.embed_texts()           → list[list[float]]
    → vector_store.add_chunks()        → 内存向量库就绪

运行时（每次 /ask）：
  POST /ask {"query": "..."}
    → retriever.retrieve(query)        → top_k=10 候选
    → reranker.rerank(query, chunks)   → top_n=1 最佳
    → build_prompt(query, chunks)      → 拼 prompt
    → llm_client.generate(prompt)      → 生成答案
    → AskResponse(answer, sources)     → JSON 返回
```

## 四、关键技术决策

| 决策 | 理由 |
|------|------|
| Ollama 本地部署 | 不依赖云 API，数据不出本地 |
| OpenAI SDK 调 Ollama | Ollama 提供 /v1/ 兼容端点，切换厂商只改 URL |
| 余弦相似度 | 向量方向代表语义，天然归一化 |
| 检索(10) + 重排(1) 两阶段 | Bi-Encoder 快但粗，精排后只给 LLM 最相关的一条 |
| SHA256 增量索引同步 | 避免每次重启全量重建，只处理新增/修改/删除 |
| chunk overlap=50 | 防止关键信息落在 chunk 边界被切断 |
| 按空白字符切分 | 避免把中文词/英文单词从中间切断 |

## 五、面试常见追问

**Q: 为什么用 RAG？**
A: LLM 知识有截止日期且容易幻觉。RAG 让模型基于真实文档回答，可溯源可更新。

**Q: chunk overlap 有什么用？**
A: 防止关键信息刚好在 chunk 边界上，overlap 让相邻 chunk 有上下文连续性。

**Q: 为什么先检索再重排？**
A: 检索（Bi-Encoder）速度快、召回广（10个候选）；重排更精准。两阶段平衡速度与精度。

**Q: 索引同步怎么实现？**
A: 基于 SHA256 哈希：磁盘文件 vs registry 记录对比 → 新增/修改/删除三类增量处理。

**Q: 怎么防止模型乱编？**
A: Prompt 明确指令"资料不足就回答不知道"，精排只给最相关的 chunk，减少噪声。

  ## 二、数据模型层 — app/schemas/rag.py

  这是整个项目的"类型宪法"，所有模块都基于这些模型通信。

  from pydantic import BaseModel

  class Document(BaseModel):
      source: str      # 文件名，如 "doc1.txt"
      text: str        # 文件全文
      doc_id: str      # 系统内部主键，相对路径，如 "misc/novel_excerpt.txt"

  > Document 是从磁盘读出来的原始文档。doc_id ≠ source：doc_id 是唯一标识（用于索引同步），source 是给人看的。

  class Chunk(BaseModel):
      doc_id: str      # 来自哪个 Document
      source: str      # 文件名
      chunk_id: int    # 该文档内第几个 chunk（从0开始）
      text: str        # chunk 文本内容

  > Chunk 是 Document 切分后的片段。面试重点：为什么切 chunk？因为 LLM 有 context window 限制，且 embedding 对长文本效果差，切成小块检索更精准。

  class RetrievedChunk(BaseModel):
      source: str
      chunk_id: int
      text: str
      score: float     # 检索/重排的相似度分数
      doc_id: str

  > RetrievedChunk 是 Chunk + 和 query 的相似度分数。检索和重排阶段用。

  class SourceItem(BaseModel):
      source: str
      doc_id: str
      chunk_id: int

  > SourceItem 是返回给 API 用户的来源信息。注意：它不包含 text 和 score，只暴露给用户最低限度的来源引用。这和 RetrievedChunk 是不同的职责——内部用
  > RetrievedChunk，外部用 SourceItem。

  class DocRegistryItem(BaseModel):
      doc_id: str
      source: str
      content_hash: str    # 文档内容的 SHA256，用于检测文档是否变化
      chunk_count: int     # 该文档被切成几个 chunk

  > DocRegistryItem 是索引同步的核心。记录了每个文档的哈希，下次启动时对比哈希就知道文档是新增/修改/删除。

  class AskRequest(BaseModel):
      query: str

  class AskResponse(BaseModel):
      answer: str
      sources: list[SourceItem]

  > API 的请求/响应模型。FastAPI 会自动根据 Pydantic 模型做校验和序列化。

  ### 3.1 app/services/loader.py — 文档加载器

  from pathlib import Path
  from app.schemas.rag import Document

  def load_documents(data_dir: str) -> list[Document]:
      base_path = Path(data_dir)
      if not base_path.exists():
          raise FileNotFoundError(f"目录不存在: {data_dir}")

      documents = []
      for file_path in base_path.rglob("*"):    # 递归扫描所有子目录
          if not file_path.is_file():
              continue
          if "index" in file_path.parts:        # 排除 index 目录本身
              continue
          if file_path.suffix.lower() not in {".txt", ".md"}:  # 只处理 txt/md
              continue
          text = file_path.read_text(encoding="utf-8").strip()
          if not text:                           # 跳过空文件
              continue

          doc_id = str(file_path.relative_to(base_path)).replace("\\", "/")
          documents.append(Document(doc_id=doc_id, source=file_path.name, text=text))
      return documents

  > 面试讲法：加载器负责把 data/ 下所有 .txt 和 .md 文件读进来。rglob("*") 递归扫描子目录。doc_id 用相对路径（如 misc/novel_excerpt.txt），解决了子
  > 目录下同名文件的问题。排除 index 目录防止把索引文件当作文档。

  ### 3.2 app/services/chunker.py — 文本分块器

  def split_text(text: str, chunk_size: int = 200, overlap: int = 50) -> list[str]:

  > 参数：chunk_size=200 每个块最多 200 字符，overlap=50 相邻块重叠 50 字符。

      while start < text_length:
          ideal_end = min(start + chunk_size, text_length)
          end = ideal_end

          # 如果还没到文本末尾，尽量往前找空白字符，避免把单词/中文词切开
          if end < text_length:
              min_end = min(start + max(1, chunk_size // 2), text_length)
              while end > min_end and not text[end - 1].isspace():
                  end -= 1
              if end == min_end and not text[end - 1].isspace():
                  end = ideal_end    # 实在找不到合适边界就硬切

  > 面试重点：这是"智能切分"——不是简单按 200 字符硬切，而是往前走找到空白字符（空格/换行）作为切分点，避免把词从中间切断。如果退到一半还没找到空白就
  > 硬切，保证至少有一半的 chunk_size。

          chunk = text[start:end].strip()
          if chunk:
              chunks.append(chunk)

          if end >= text_length:
              break

          # 下一段从 end - overlap 开始，保留重叠区
          next_start = max(0, end - overlap)
          while next_start < text_length and text[next_start].isspace():
              next_start += 1
          if next_start <= start:
              next_start = start + 1    # 防止死循环
          start = next_start

  > 面试重点：重叠（overlap）的作用——防止关键信息刚好落在两个 chunk 的边界上，导致检索时漏掉。比如"FastAPI 支持依赖注入"这句话如果被切成两半，
  > overlap 保证它在相邻 chunk 中都有出现。

  def split_documents(documents: list[Document], ...) -> list[Chunk]:

  ### 3.4 app/services/vector_store.py — 向量存储与检索

  class InMemoryVectorStore:
      def __init__(self):
          self.records: list[tuple[Chunk, list[float]]] = []

  > 最简单的内存向量库：一个列表，每个元素是 (Chunk, embedding向量)。

      def add_chunks(self, chunks, embeddings):
          for chunk, embedding in zip(chunks, embeddings):
              if not chunk.text.strip() or not embedding:
                  continue
              self.records.append((chunk, embedding))

      def search(self, query_embedding, top_k=5) -> list[RetrievedChunk]:
          # 计算 query 向量的模
          query_norm = sqrt(sum(x*x for x in query_embedding))
          if query_norm == 0:
              return []

          retrieved = []
          for chunk, embedding in self.records:
              emb_norm = sqrt(sum(x*x for x in embedding))
              if emb_norm == 0:
                  continue
              # 余弦相似度 = dot(A,B) / (|A| * |B|)
              dot = np.dot(query_embedding, embedding)
              score = dot / (query_norm * emb_norm)
              retrieved.append(RetrievedChunk(..., score=score))

          retrieved.sort(key=lambda x: x.score, reverse=True)
          return retrieved[:top_k]

  > 面试重点：为什么用余弦相似度而非欧氏距离？向量 embedding 的方向比绝对大小更重要，余弦相似度只关心角度，天然归一化到 [-1, 1]，语义相似度高就更接
  > 近 1。

  ### 3.5 app/services/retriever.py — 检索器

  class Retriever:
      def __init__(self, embedder, vector_store):
          self.embedder = embedder
          self.vector_store = vector_store

      def retrieve(self, query: str, top_k: int = 10) -> list[RetrievedChunk]:
          query_embedding = self.embedder.embed_text(query)
          return self.vector_store.search(query_embedding, top_k=top_k)

  > 检索器 = embedder + vector_store 的组合。把 query 转成向量 → 在向量库里搜 top_k 个最相似的 chunk。top_k=10 给 reranker 留足够候选。

  ### 3.6 app/services/reranker.py — 重排序器

  class Reranker:
      def __init__(self):
          self.embedder = BiEncoderEmbedder()
          self.vector_store = InMemoryVectorStore()

      def rerank(self, query, chunks, top_n=3):
          query_embedding = self.embedder.embed_text(query)
          for chunk in chunks:
              embedding = self.embedder.embed_text(chunk.text)
              s = 0
              # 统计 query 和 chunk 向量中相同位置且非零的元素个数
              for i in range(len(embedding)):
                  if embedding[i] == query_embedding[i] and embedding[i] != 0:
                      s += 1
              chunk.score = s
          chunks = sorted(chunks, key=lambda x: x.score, reverse=True)
          return chunks[:top_n]

  > ⚠️ 实话实说：这个 reranker 比较简陋，不是真正的 Cross-Encoder reranker。它只是统计向量中相同位置"恰好相等"的元素个数，对浮点数 embedding 来说几 乎
  > 不会相等，所以实际效果有限。面试时可以说：这里是一个简化版 reranker，生产环境应该换成 Cross-Encoder（如 bge-reranker）或 LLM-based reranker。

  ### 3.7 app/services/prompt_builder.py — Prompt 构造

  def build_prompt(query: str, chunks: list[RetrievedChunk]) -> str:
      parts = []
      parts.append("你是文档问答助手，只能基于提供的资料回答；如果资料不足，就明确回答"不知道"。")
      parts.append("")

      for idx, chunk in enumerate(chunks, start=1):
          parts.append(f"资料{idx}（source={chunk.source}, chunk_id={chunk.chunk_id}）:")
          parts.append(chunk.text)
          parts.append("")

      parts.append(f"问题：{query}")
      return "\n".join(parts)

  > 标准 RAG prompt 模板：先给系统指令（只基于资料回答），再把检索到的 chunk 作为"资料1、资料2..."拼进去，最后放用户问题。这样 LLM 就"有据可依"。

  ### 3.9 app/services/rag_pipeline.py — 主流程编排

  class RAGPipeline:
      def __init__(self, retriever, reranker, llm_client):
          self.retriever = retriever
          self.reranker = reranker
          self.llm_client = llm_client

      def ask(self, query: str) -> AskResponse:
          # Step 1: 检索
          retrieved = self.retriever.retrieve(query, top_k=10)
          # Step 2: 重排
          reranked = self.reranker.rerank(query, retrieved, top_n=1)
          # Step 3: 构造 prompt
          prompt = build_prompt(query, reranked)
          # Step 4: LLM 生成
          answer = self.llm_client.generate(prompt)

          # Step 5: 构造 sources（按 doc_id 去重）
          filtered_chunks = []
          pasted = {}
          for item in reranked:
              if item.doc_id in pasted:
                  continue
              pasted[item.doc_id] = 1
              filtered_chunks.append(item)

          sources = [SourceItem(source=item.source, doc_id=item.doc_id,
                                 chunk_id=item.chunk_id) for item in filtered_chunks]

          return AskResponse(answer=answer, sources=sources)

  > 面试重点：这是整个系统的"编排器"——4 步走：Retrieve → Rerank → Prompt → Generate → 返回。sources 按 doc_id 去重，保证每个文档只在来源列表里出现一
  > 次。这是典型的"管道模式"（Pipeline Pattern）。

  ### 3.10 app/services/index_store.py — 索引同步（最重要模块）

  这是整个项目工程复杂度最高的模块。

  def compute_content_hash(text: str) -> str:
      return hashlib.sha256(text.encode("utf-8")).hexdigest()

  > 用 SHA256 对文档内容做哈希，用于判断文档是否变化。

  def sync_index(data_dir, index_dir) -> list[Chunk]:
      docRegistryItems = load_doc_registry(index_dir)   # 加载上次的索引元数据
      documents = load_documents(data_dir)               # 扫描当前所有文档
      old_chunks = load_chunk(index_dir)                 # 加载上次的所有 chunk

  > 三个数据源：上次的 registry、当前磁盘上的文档、上次的 chunks。

      change = []  # 内容变化的文档
      delete = []  # 已删除的文档
      new = []     # 新增的文档
      pasted = {}
      for document in documents:
          pasted[document.doc_id] = 1
          content_hash = compute_content_hash(document.text)
          if document.doc_id not in docRegistryItems:      # registry 里没有 → 新文档
              new.append(document)
              continue
          if docRegistryItems[document.doc_id].content_hash == content_hash:
              continue                                      # 哈希相同 → 没变化，跳过
          change.append(document)                           # 哈希不同 → 文档被修改

      # 找出被删除的文档：registry 里有但磁盘上没有了
      for registry in docRegistryItems.values():
          if registry.doc_id not in pasted:
              delete.append(registry.doc_id)

  > 面试重点：这是增量索引同步的核心逻辑。不是每次都全量重建（那样太慢），而是通过哈希对比做增量更新。三类变更：
  >
  > - 新增：磁盘有、registry 没有
  > - 修改：磁盘有、registry 有、但哈希不同
  > - 删除：registry 有、磁盘没有

      # 处理删除：从 old_chunks 中移除被删文档的 chunk
      for registry in delete:
          old_chunks = [chunk for chunk in old_chunks if chunk.doc_id != registry]

      # 处理修改：移除旧 chunk → 重新分块 → 加入新 chunk → 更新 registry
      for document in change:
          old_chunks = [chunk for chunk in old_chunks if chunk.doc_id != document.doc_id]
          new_chunk = split_documents([document])
          old_chunks.extend(new_chunk)
          doc_registry[document.doc_id] = DocRegistryItem(...)

      # 处理新增：分块 → 加入 → 写入 registry
      for document in new:
          new_chunk = split_documents([document])
          old_chunks.extend(new_chunk)
          doc_registry[document.doc_id] = DocRegistryItem(...)

      save_doc_registry(index_dir, doc_registry)
      save_chunk(index_dir, old_chunks)
      return old_chunks

  > doc_registry.json 存的格式是 {doc_id: {source, content_hash, chunk_count}}。chunks.jsonl 每行一个 Chunk 的 JSON。

  ### 5.2 app/core/pipeline.py — 启动时组装管道

  def build_pipeline() -> RAGPipeline:
      BASE_DIR = Path(__file__).resolve().parent.parent  # 即 app/
      DATA_DIR = BASE_DIR / "data"
      INDEX_DIR = BASE_DIR / "index"

      # 第一步：索引同步（增量更新）
      chunks = sync_index(str(DATA_DIR), str(INDEX_DIR))

      # 第二步：为所有 chunk 生成 embedding 并建向量库
      embedder = BiEncoderEmbedder(model="qwen3-embedding:0.6b-fp16")
      vector_store = InMemoryVectorStore()
      chunk_texts = [chunk.text for chunk in chunks]
      embeddings = embedder.embed_texts(chunk_texts)
      vector_store.add_chunks(chunks, embeddings)

      # 第三步：组装
      retriever = Retriever(embedder=embedder, vector_store=vector_store)
      reranker = Reranker()
      llm_client = LLMClient()

      return RAGPipeline(retriever=retriever, reranker=reranker, llm_client=llm_client)

  pipeline = build_pipeline()  # 模块级单例，导入时执行一次

  > 面试重点：启动时执行一次 sync_index（增量同步），然后对所有 chunk 做 embedding 建向量库。这是启动时初始化模式，缺点是重启需要重新 embedding（未
  > 持久化）。
